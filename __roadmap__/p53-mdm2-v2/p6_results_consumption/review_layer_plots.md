## Step 1: Curve-geometry builder + committed Review layer
**Goal**: Turn the Analysis layer's time samples into renderable geometry in a separate Review SubLayer, with the plot's coordinate mapping carried on the stage so it is invertible rather than baked into the builder.
**Implementation Logic**:
The Analysis layer already holds everything a plot needs; nothing is recomputed here and no simulation is re-run. Read the series back off a composed stage — never from a builder's in-memory state — and emit, per genotype variant, one linear `UsdGeomBasisCurves` prim per model node. Linear curves need `points` and `curveVertexCounts` only; `basis` does not apply to the linear type, and `widths` is what makes the curve visible rather than infinitely thin.

The coordinate problem is the substance of this step, not an afterthought. The stage is Ångström-scaled (`metersPerUnit = 1e-10`) and the complex spans tens of units, so probability values in [0,1] plotted against 500 frames are unusable in world space without an explicit mapping. Place the whole plot under one `Xform` beside the complex and record the mapping as attributes on the plot Scope — the frame range, the probability range, and the world-space width and height the plot box occupies. Recording the mapping rather than hard-coding it is what makes the read-back check in Step 2 possible at all: a reader can invert stage units back to (frame, probability) using only what the stage says.

Author an axis frame (two more linear curves) and a `UsdGeomCamera` aimed at the plot box so the layer carries its own viewpoint, which is the Review department's stated content. Assign per-node display colors so the five node curves are distinguishable, taking `primvars:displayColor` rather than inventing a new attribute. Keep every new attribute under a `bio:review:` sub-namespace, consistent with the existing per-domain split (`bio:md:`, `bio:mutation:`, `bio:ddg:`, `bio:maboss:`).
**Deliverables**: `examples/p53_mdm2/templates/build_review_layer.py` — `build_review_layer()`, `PlotAxes` dataclass carrying `frame_range`/`prob_range`/`plot_width`/`plot_height`, `REVIEW_SCOPE`, `CURVE_ATTR_PREFIX`, `_curve_points()`; `examples/p53_mdm2/review/p53_mdm2_review.usda` — committed Review layer with a `review/` Scope per variant, one `BasisCurves` per node, an axis frame, a `Camera`, and the `bio:review:frameRange`/`bio:review:probRange`/`bio:review:plotWidth`/`bio:review:plotHeight` mapping attributes

## Step 2: Read-back check against the Analysis time samples
**Goal**: Prove the curves are the data rather than a picture of it, by asserting each vertex against the observable it was drawn from, read off the same freshly opened stage.
**Implementation Logic**:
This is the property that earns the geometry its place in USD under R15's opacity rule, so it is tested rather than asserted. Open the composed stage fresh, read the recorded axis mapping off the plot Scope, invert it per vertex, and compare against `bio:maboss:prob:<node>` at the corresponding time code — following the suite's standing discipline that a read-back test asserts committed artifacts against expectations derived independently, never against the generator's own state. Import attribute *names* from the builder and no values, as `tests/test_integrated.py` already does.

Add the non-destructiveness half in the same module: open the Analysis layer alone and assert it carries no `review/` Scope and no `bio:review:` attribute, mirroring the existing Biology-layer assertion. Report the observed maximum absolute difference per node in the check output rather than only a pass flag, so a mismatch is diagnosable from the suite output alone and so the number is recoverable for the Progress table. The harness has no skip concept and reads `passed` as a bool, so return zero rows when the Review layer is absent rather than emitting a failing row.
**Deliverables**: `examples/p53_mdm2/tests/test_review_layer.py` — `run()` returning rows `review_curve_matches_timesamples`, `review_axis_mapping_present`, `review_absent_from_analysis_layer`, `review_camera_authored`; `examples/p53_mdm2/tests/run_tests.py` — new `review` layer registered

## Step 3: Compose the Review layer and record what usdview shows
**Goal**: Put the Review layer at the top of the departmental stack where a re-review can override without touching analysis, and capture an honest observation of the rendered result.
**Implementation Logic**:
Add the Review layer as the strongest entry of the integrated root layer's `subLayers` list, ahead of Analysis. Strongest is correct for the same reason Analysis sits above Perturbation: a review opinion annotates everything beneath it and must be overridable last. The root layer keeps its existing contract — it adds only the SubLayer list, the root-layer-only stage metadata, the Local `Genotype` selection, and the `integration/` join — so this is one list entry and no new pipeline data.

Then open the composed stage in `usdview` in an attended session and record what is actually on screen: which camera the viewer picks by default, whether the curves are visible at the complex's scale, and whether timeline scrubbing moves anything. Commit the screenshot and a short note. Cycle-007's gate audit found that gates predicting an outcome get falsified by the evidence, so this step records the observation and leaves any judgement about legibility to the follow-up that the observation itself justifies. Update the README's LIVERPS table and its "Not yet done" entry for the Review layer to match what now exists.
