# Raw MaBoSS State-Space Output as a Payload

**Goal**: Stop discarding MaBoSS's own output files, commit one run directory as the evidence of record, and attach the full state-space probability trajectory to the Analysis layer through a **Payload** arc — giving the campaign its first exercised Payload arc and putting the raw simulation output in the arc the design doc reserves for raw data.
**Pre-conditions**:
- [ ] `run_maboss.run_cfg()` currently runs into a `tempfile.mkdtemp` and keeps only `get_nodes_probtraj()`, so MaBoSS's `*_probtraj.csv`, `*_fp.csv` and `*_statdist.csv` are written and then lost [source: `examples/p53_mdm2/maboss/run_maboss.py`]
- [ ] The reference `.cfg` sets `sample_count = 50000`, `statdist_traj_count = 100`, `max_time = 50`, `time_tick = 0.1`, `seed_pseudorandom = 100`, `thread_count = 1`, so a re-run is deterministic and the state-space grid is 500 report times [source: `examples/p53_mdm2/maboss/reference/p53_Mdm2_runcfg.cfg`]
- [ ] R15 boundary rule accepted: inputs and observables live in USD; raw run output is what the Payload arc is for
**Success Gates**:
- ⬜ `[static]` One MaBoSS run directory per variant is committed verbatim under `examples/p53_mdm2/maboss/output/`, containing the files the binary itself wrote, with a provenance record naming the binary version, the seed and the sample count — and no file in it ends in `.log`, since `.gitignore` swallows that extension
- ⬜ `[static]` The `subLayers`-composed Analysis layer authors a `payload` arc on each `maboss/<variant>` prim; the payloaded layers contain state-space data and no atom, `mdSetup`, `integration/` or `bio:maboss:prob:<node>` opinion
- ⬜ `[run]` Opening the composed stage with `Usd.Stage.Open(path, Usd.Stage.LoadNone)` resolves the Local `bio:maboss:prob:<node>` time samples but resolves **no** `bio:maboss:stateProb` attribute; after `stage.Load()` on the variant prim the same attribute resolves. Both observations are recorded, along with the on-disk size of each payload layer — the size is reported, not claimed to be large
- ⬜ `[run]` A read-back check recomputes each node's marginal probability by summing the payloaded state probabilities over the states in which that node is ON, compares it against the Analysis layer's existing `bio:maboss:prob:<node>` at the same time code, and reports the per-node maximum absolute difference in its output line; the observed values are recorded in this leaf's Progress notes
- ⬜ `[run]` `usdchecker` exits 0 on the composed stage and `tests/run_tests.py` reports zero failures

## Step 1: Persist MaBoSS run output instead of discarding it
**Goal**: Make the binary's own output a durable artifact, since everything downstream — the payload, any native plot, any future re-analysis — needs files that currently exist only inside a temporary directory.
**Implementation Logic**:
`run_cfg` sanitises the model into a temp directory, runs, reads one DataFrame and lets the rest evaporate. Redirect the run into `maboss/output/run_<UTC>/<variant>/` instead, per the project's standing rule that per-run directories keep concurrent runs from overwriting each other's evidence. Keep the pyMaBoSS default `res` prefix and the flat one-directory layout, because that is exactly the layout `maboss.StoredResult` expects and the sibling `native_plots/` leaf will consume it unchanged.

Extend the parsed result to carry the state-space series alongside the node marginals it already carries: a stable ordered list of state labels and, per report time, the probability of each. Keep the existing no-pandas-leaks contract — convert to plain Python inside this module as `run_cfg` already does for the node marginals — so tests and builders stay free of a pandas dependency. Nodes never ON in any state do not appear in state labels; record that rather than padding, since it is a property of the model output and a reader needs to know it.

Commit exactly one run directory as the evidence of record, following the precedent set by `data/ddmut_ppi_live/`, where verbatim third-party response bodies are committed as the thing a test asserts against. Ignore subsequent `run_*` directories so repeated runs do not accrete in the history.
**Deliverables**: `examples/p53_mdm2/maboss/run_maboss.py` — `run_dir()`, `StateTraj` dataclass with `labels`/`prob_by_frame`, `ProbTraj.states` field, `run_cfg(..., keep_dir=)`; `examples/p53_mdm2/maboss/output/run_<UTC>/` — the committed reference run, one subdirectory per variant plus a `provenance.json` naming binary version, seed, sample count and time grid; `.gitignore` — rule keeping only the committed reference run

## Step 2: Author the state-space payload layers and attach the arc
**Goal**: Put the state-space trajectory behind a Payload arc so the campaign exercises the arc the design doc reserves for raw data, and so the Analysis layer stays as light to open as it is today.
**Implementation Logic**:
Emit one layer per variant carrying a uniform `token[]` of state labels and a time-sampled `float[]` of per-state probabilities over the same frame grid the Analysis layer already uses, so a reader can index the array by the label list without consulting the CSV. Attach each layer to its existing `maboss/<variant>` prim with a payload arc rather than a reference, and author it from the Analysis-layer builder so both halves are written in one pass and cannot drift apart.

The arc choice is the point of the step. Payloads sit below Local in LIVERPS, so the node marginals the Analysis layer authors locally continue to win and continue to resolve with the payload unloaded — the stage keeps its cheap, always-available summary and gains an on-demand raw layer beneath it. State honestly in the layer documentation that at this model size the payload is small; the arc is correct on semantics and on how it generalises to a model with more nodes, not on present-day memory pressure, and a gate that claimed otherwise would be falsified by its own size measurement.
**Deliverables**: `examples/p53_mdm2/templates/build_analysis_layer.py` — `build_state_payloads()`, `STATE_LABELS_ATTR`, `STATE_PROB_ATTR`, payload attachment in `build_analysis_layer()`; `examples/p53_mdm2/analysis/payloads/p53_mdm2_states_<variant>.usda` — four committed payload layers; `examples/p53_mdm2/analysis/p53_mdm2_analysis.usda` — regenerated with the four payload arcs
**Consistency Checks**: `PYTHONPATH="/Users/hacker/Documents/bin/OpenUSD/lib/python:$(pwd)/examples:$PYTHONPATH" /Users/hacker/Documents/src/AOUSD/forOUSD/bin/python3 -c "from pxr import Usd, Sdf; s = Usd.Stage.Open('examples/p53_mdm2/analysis/p53_mdm2_analysis.usda', Usd.Stage.LoadNone); p = [x for x in s.Traverse() if x.HasAuthoredPayloads()]; assert len(p) == 4, [str(x.GetPath()) for x in p]"` (expected: PASS)

## Step 3: Deferred-load and marginalization read-back checks
**Goal**: Observe that the payload actually defers, and cross-check the summary already in USD against the raw data now beneath it — an oracle the campaign has not had for hop 4.
**Implementation Logic**:
Two independent observations. First, deferred loading: open the composed stage with `LoadNone`, record which attributes resolve and which do not, then load the variant prim and record the change. This is the only gate that distinguishes a payload from a reference, so it is the one worth writing; the stage glossary's own definition of the arc is that payloads are not traversed greedily under `LoadNone`.

Second, marginalization. The node marginals in the Analysis layer are a reduction of the state-space series, so summing payloaded state probabilities over the states in which a node is ON must reproduce them. Split the `" -- "`-joined state labels to decide node membership. This is a genuinely independent oracle — a different code path over a different file — and it fits the suite's standing rule that read-back asserts against expectations derived from the source data rather than the generator's state. Report the observed maximum absolute difference per node rather than a bare pass flag: a large difference would be a finding about the two MaBoSS outputs, not about this builder, and the number is what makes that distinguishable. Return zero rows when the payload layers are absent, since the harness reads `passed` as a bool and has no skip concept.
**Deliverables**: `examples/p53_mdm2/tests/test_state_payload.py` — `run()` returning rows `payload_arc_authored`, `payload_deferred_under_loadnone`, `payload_resolves_after_load`, `payload_marginals_match_node_probs`, `payload_layer_sizes_recorded`; `examples/p53_mdm2/tests/run_tests.py` — new `readback-payload` layer registered
