Six structures that are not directed process flow.

Plate 04 covers one family well: things that flow left to right, with or without a real magnitude. That's a real gap when a reference system is meant to last years across every field — a wet-lab protocol, a systems paper, and a policy study don't all reduce to a pipeline. Rather than pick a third time and build the wrong one at full depth, this plate sketches all six requested structures at low fidelity: enough to judge the visual direction and mark vocabulary, not enough to call finished.

None of these are closed sets yet — no ink-budget proof, no poster-distance stress test, no theme-contrast checks. That work only happens for whichever ones earn a place. Reroll any panel to see it hold across different data; reroll the theme to see it hold across palettes.

Reads on

Every sketch is live SVG. This file intentionally doesn't share code with methods-kit.js — building the shared abstraction now, before knowing which structures survive, would be premature.

Theme
01

The six sketches

Each panel: what the structure is for, the sketch itself, and the specific risk it carries if promoted to a full kit.

Actor / lifeline sequence

Who messages whom, in order — an instrument-and-operator protocol, a distributed system's request path, a multi-party study procedure. Time runs top to bottom, not left to right.

Risk: message-label collisions on a dense exchange (6+ messages) — needs the same deconflict pass as the chart kit's series labels before it's a kit.

Gantt / project timeline

Phase durations and overlap — when the method itself has a project shape (recruitment overlapping baseline, a multi-season field campaign). Answers "how long" and "what ran concurrently," which flow diagrams can't.

Risk: reads as a bar chart, competing with the chart kit's own ranked-bar form — needs a clear rule for when a poster gets one or the other, not both.

Nested component / architecture

Containment, not flow — a system's modules, a codebase's layers, an apparatus's subassemblies. The relationship being drawn is "part of," which no arrow can honestly express.

Risk: nesting depth is unbounded in principle; a real kit needs a hard depth cap (two levels, as sketched) or it invites a poster-sized org chart.

State machine

States and the conditions that move between them — an instrument's operating modes, a robot's control logic, a protocol with real branching (the fixed fan-out in Plate 04 still can't do this). The self-loop shown is a state that can re-enter itself.

Risk: edge-label collisions and line crossings scale badly past ~5 states — would need either a fixed canonical layout per state count or an explicit "too complex, use a table" escape hatch.

Factorial / matrix design

Condition × condition, the experimental design itself rather than its results — a 2×2, a dose × timepoint grid. Closest of the six to Plate 03's chart-vs-table guidance: this is the "table" side of that decision, drawn instead of set in body text.

Risk: only really reads past 2×2 or 2×3 — beyond that it is a table and should be typeset as one, not forced into this diagram.

Undirected network

Relationships with no inherent direction — site co-occurrence, protein interaction, citation or collaboration structure. The hub layout here is hand-placed; a real kit would need an actual force-layout pass or a rule restricting it to small, pre-clustered graphs.

Risk: hand-placed or naively-radial layouts don't generalise past ~8 nodes without edge crossings a reader will misread as meaningful.

02

What this plate asks you to decide

One decision: which of these six, if any, get built out to the same standard as the flow and sequence kits.

Building all six to full depth is the wrong default

Each promoted structure needs its own ink-budget check, poster-distance stroke/type audit, theme-contrast proof, and closed-vocabulary decision — the same investment Plates 03 and 04 took. Six of those in parallel is how a reference system stops being a system. Picking one or two, well, keeps the "designer's liberty vs. system cohesion" tension the brief named from the start resolved in the system's favour.
