A different kind of closed set than the chart or methods kit.

The chart kit is closed on form — four chart types, full stop. Pictograms can't work that way: "subject," "sample," "site," "model," "citation" is an open, field-specific vocabulary, and no fixed icon set could cover every lab's posters for years to come. What can be closed is construction — the grid, stroke weight, corner rounding, and colour rule every pictogram obeys — so that whoever draws the fortieth icon this system will ever need produces something that visibly belongs next to the first.

The payoff is the same "portable literacy" argument the methods kit made for its layout: a reader who has seen this lab's subject icon once should recognise it instantly on every poster after, at any size, in any theme. That only holds if the same concept always gets the same icon — a construction rule without a reuse rule is just a nicer-looking way to draw something different every year.

The construction rules

Five tokens. Every pictogram in the starter library below, and every one a future poster adds, is checked against these — not redrawn from taste each time.

TokenValueWhat it fixes
grid24 unitsEvery icon is drawn on the same square grid, so unrelated icons still share optical scale.

02

Two size tiers, one physical scale

Inline sits at the sheet's own type floor — a pictogram is never allowed to be smaller than the smallest legal word next to it. Standalone is exactly double, for legends, actor markers, and anywhere an icon carries its concept alone.

Toggle the construction grid off above to see the same eight read as a finished set rather than a diagram of their own rules.

03

The one accent event, here too

Same rule as the chart and methods kits, restated so it survives being read on its own: at most one pictogram per figure may take the accent colour, and only to mark the one thing the figure is actually about.

A legend where every icon is accent-coloured has the same defect as a chart with three highlighted bars: it stops telling the reader where to look. If a poster needs to distinguish several categories at once, that is the chart kit's categorical scale's job (Plate 03), not the pictogram set's.

04

What this plate asks you to decide

Three decisions, plus one process to adopt.

  1. Construction is closed; vocabulary is open, by design. Confirm that's the right split — an alternative is a small fixed icon set (as some poster templates ship), which is simpler but will visibly run out within a year or two of real use across fields.
  2. Stroke-to-grid ratio of 1:10. Chosen because it lands standalone-size pictograms within 1% of the chart kit's own data-stroke floor — the two kits agreeing on "how thick is a mark" without being told to. Worth a real print check alongside Plate 01's ink ceilings and Plate 03's ppi floors before it hardens.
  3. The reuse rule needs an owner, not just a page. "Same concept, same icon, forever" only works if new icons get checked against this plate before they ship. Decide whether that's a lightweight habit (check this page first) or something the studio should enforce with an actual shared icon file future posters import.

This plate does not decide

  • The hero illustration slot and its ink allowance
  • Which concepts beyond these eight get drawn next — that should follow real posters, not be guessed here

Known soft spots

  • The corner-radius rule is stated as a ratio but not yet enforced pixel-exactly across all eight starter icons — citation and computation deviate slightly. Worth a pass before this becomes the reference file.
  • Eight icons is enough to prove the rules, not enough to be useful yet — treat this as the construction spec, not the finished library.
  • No test yet for how these read at the smallest inline size printed, only on screen — same caveat as every mm-based floor in this system until a real print check happens.
