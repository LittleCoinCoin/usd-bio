The evidence base names this the format's weak point, and "protocol" is not only a clinical trial.

The RCT behind this canon found IMRAD-structured posters win on details and rigor by a wide margin — the guidelines already made methods and limitation mandatory sections on that basis. But "mandatory section" only guarantees the words exist; it says nothing about whether a stranger can reconstruct your method from across the aisle. §7's instruction — "methods are drawn, not written" — holds for a beam line, a synthesis route, a genomics pipeline, a CPU microarchitecture, a policy process, and a numerical experiment's parameter sweep, not only a two-arm trial. The first draft of this kit forgot that; this one doesn't.

Two compositions cover the difference. Flow-with-magnitude is for any method where a real count shrinks or splits across stages — trial attrition, but equally a materials-screening funnel, a specimen count through field sampling, or simulation runs surviving convergence: a ribbon's width is that count, not decoration standing in for it. Plain sequence is for methods with no meaningful per-stage count at all — an optical bench, a computer architecture, a policy process, a computational pipeline — where the thing worth drawing is structure and order, not magnitude. Six marks compose both — ribbon, stage tick, direction chevron, magnitude badge, sequence axis, node+connector — closed, like the chart kit.

What a chip was standing in for

v1's methods block is a rounded rectangle with a coloured left border and three lines of prose — the exact silhouette this canon's own anti-pattern list warns against elsewhere in the system. It survives because nothing replaced it. Below, the same protocol told both ways.

Text chip current

Legible only as prose. A reader has to read every word to learn there were two arms, how many subjects, and how many were lost along the way — and the chip cannot show that last part at all.

Attrition flow this plate

Legible as shape before a word is read: one pool splits, one arm visibly thins more than the other, one bends away from standard care. Width is dropout — the diagram states a number the chip could only footnote.

02

The six marks

Built once as marks, composed two ways in sections 03 and 04. Each mark holds the same type floor as the chart kit — 7.06mm / 20pt minimum — because a methods diagram read at the same distance as a data figure gets no exemption.

The one accent event, applied here

The accent fills exactly one condition — the one that deviates from the standard or baseline case — and marks exactly one point on it: where the deviation happens. Width and node fill, by contrast, are never accent-coloured; they stay ink-soft everywhere, so the reader's eye is pulled by colour to which condition and by shape to how it changed, never both at once.

03

Flow-with-magnitude, across five fields

One shared pool splits into two conditions; ribbon width at every point is the real count there. The example rotates on reroll — the composition rule doesn't change, only the field does.

The composition rule is fixed, not templated per-poster: one shared origin, conditions diverge left to right in the order they were formed, an axis (time, iteration, or whatever the method actually steps through) runs along the bottom when there is one, magnitude badges always trail their ribbon. A reader who has seen one of these posters can read the next one's methods without re-learning the layout — the same "portable literacy" argument the canon already makes for the fixed zone geometry.

04

Plain sequence — when nothing has a meaningful width

An optical bench, a CPU pipeline, a policy process and a bioinformatics pipeline have no headcount to shrink. Structure and order are the whole story, so the ribbon disappears and a plain node chain replaces it — shape carries meaning (rect = process, diamond = decision, cylinder = data store), and a connector's line style (solid, dashed, dotted) can mark a required, optional, or inferred step.

05

What this plate asks you to decide

Three decisions.

  1. Two compositions, one closed set of six marks. Flow-with-magnitude (ribbon, stage tick, magnitude badge, sequence axis) for anything with a real count that changes; plain sequence (node, connector) for anything that doesn't. Between them: trials, screening funnels, field sampling, simulation sweeps, optical setups, hardware block diagrams, bioinformatics pipelines, policy processes. Confirm this is the actual range of methods your posters need — a genuinely branching decision tree (not a fixed fan-out) is still unserved by either.
  2. The domain examples are illustrative, not exhaustive. Five flow domains and four sequence domains rotate through sections 03–04 so the composition reads as general-purpose rather than clinical-only. If your own methods cluster around a domain not shown, say which — it's a data-generator change, not a new primitive.
  3. One accent event, carried by colour alone. Width and node fill stay neutral everywhere so the diagram never argues with itself about whether size or colour is the signal. The accent marks one condition and, on it, one deviation point.

This plate does not decide

  • The hero illustration slot and its ink allowance
  • Pictogram construction for repeated concepts
  • A true branching decision tree (as opposed to a fixed fan-out from one origin)

Known soft spots

  • Flow width uses √n so area, not width, tracks magnitude fairly — correct for perception, but means two conditions differing 4× in count look closer than 4× wide. State the badges; never let the ribbon alone carry an exact ratio claim.
  • The fixed origin-then-fan layout comfortably fits two or three conditions; four or more will crowd the vertical spread and hasn't been stress-tested.
  • Plain sequence assumes a single left-to-right chain; a real fork (e.g. a policy process with two review paths) currently has to be drawn as two separate sequence figures.
