COMPRESSION INTERPRETATION
squashfs 4.0 with `gzip` compression and a 128 KiB block size. gzip is the
oldest and most universally supported squashfs compressor, which is the
mechanical reason the 3.5.2 mount succeeded: singularity-ce 4.2.2 did not
default to a newer compressor (zstd or lz4) that a 2019 kernel/runtime pairing
might not decode. No older-compatible rebuild and no per-cluster image is
needed. Note this is a property of the current builder's default, not a
guarantee contracted anywhere -- a future builder or an explicit
`--compress` change could reintroduce the risk.

GMX VERSION-QUERY INTERPRETATION
The leaf anticipated that this query might fail naming `libcuda.so.1`, and
instructed that such a failure be read as the absence of GPU passthrough
rather than as version skew. In the event it did not fail at all: exit 0,
full version banner, no missing-library diagnostic.

The reason is that `gmx` does not link the CUDA driver library at all --
`ldd` inside the container reports no `libcuda` entry and nothing `not found`.
This agrees with the banyan SASS audit, which recorded `LIBCUDA_DT_NEEDED=no`
(sass_audit_banyan.txt). GROMACS resolves the driver lazily at the point it
actually wants a device, so a driverless invocation prints `CUDA driver: 0.0`
and exits cleanly instead of erroring.

`CUDA driver: 0.0` is therefore the expected reading of a run with no GPU
bound in, and carries no information about version skew in either direction.
It is NOT evidence that the image can use a dgx1 GPU: that remains untested
here by construction, since this leaf takes no `--nv` flag and requests no
device. The GPU smoke test on dgx1 stays PI-attended per the Q-006 policy.
